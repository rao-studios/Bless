What does the playground show?

On watching a held reply from all three sides at once.

The playground is a macOS app, a Swift package of its own beside Bless. One window holds the patient, the model and the reviewer side by side, over the ledger. It runs against Mistral with the owner's key, any model that speaks the same wire, or an offline fake that needs no key.

The patient's side shows only releases and neutral notices. The model's side shows the draft as it is written. The reviewer's side shows the queue, the conversation the policy allows, and the draft in an editor.

The pattern, in the session

The patient's Send is the pattern itself. The model is wrapped in Witnessed, so the model's pane can follow the draft. That is wrapped in Blessed, so the patient waits for a release exactly as a host's user would.

A demo in five steps

  1. Choose a scenario, such as ibuprofen with lisinopril, and press Send.
  2. Watch the model's pane write the draft while the patient sees only that it is held.
  3. Read it as the reviewer, edit it, and press Amend and Release.
  4. The patient sees the edited text, marked as reviewed and edited by the doctor.
  5. Verify the ledger: every event is there, with digests and no words.

Each fake reply holds one confident sentence a clinician would change, so the amend has something to do. The scenarios are invented; the app's guide warns against typing real patient data while a hosted model is selected.

Tested without a window

The session lives in a library with no interface, so its tests drive the whole flow on the fake model. They cover a reply held, amended, withheld, withdrawn and lapsed, and a second question that carries the first answer forward. The app's snapshot mode draws the real window off screen for pictures.

For engineers: where each piece lives
  • Run it with Examples/run.sh, or open its Package.swift in Xcode and Run. The run sheet is Examples/README.md.
  • The key comes from the app's own Keychain item, the environment, or this Mac's key store, read through /usr/bin/security; it never prints.
  • The reviewer's demo key is kept 0600 in Application Support. A real reviewer's key stays on their own device.
