Why hold the reply?

On the one rule Bless adds, and the moment it applies.

A chat pipeline has one moment where a model's words become a message someone reads. Before it, the text is a draft the system can still change. After it, the patient has read it, and the clinic answers for it.

Bless puts its gate at that moment and adds one rule: nothing reaches the recipient but a release. A release exists only after a reviewer has ruled, and it carries the ruling with it.

The rule as one wrapper

The rule lives in one type. Blessed wraps a model and is a model itself, so a host swaps one call for another and changes nothing else. Its complete runs the model, holds the draft at the Gate, and waits for the release.

The waiting happens in Gate.release(for:). It returns the release when the petition is blessed, and throws when it is withheld, lapsed or withdrawn. The host shows the patient a neutral notice then, never the reviewer's reason.

A held reply does not stream

Most chat systems stream a reply token by token. A held reply cannot, because the reviewer has not read the tokens yet. Instead, Blessed.stream reads the model's stream to its end and holds the whole reply. It sends the client one delta that carries only the petition's id.

When the release comes, the stream sends the blessed text as one piece, then the finish. A client that shows "your care team is reviewing this" needs nothing more than that first delta.

A dropped connection is not a decision

If the patient closes the app while a reply is held, the waiting call is cancelled. The petition stays pending and nothing is written: the doctor's review goes on, and the release waits for the next time the patient asks for it. Only withdraw ends a petition without a ruling.

For engineers: where each piece lives
  • The reply-held trail walks a request from Blessed.blessed through the model to Gate.submit and the wait.
  • The waiting is wake-and-recheck: every final transition wakes each waiter, and each re-reads the store. GateWaitingTests holds two waiters, a cancelled waiter and a deadline that wakes itself.
  • The Gate's methods other than release(for:) and dispatch never suspend, because the stores are synchronous. Each transition and its ledger line happen as one step on the actor.
