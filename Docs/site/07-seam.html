How does it drop into an inference layer?

On one protocol, one wrapper, and the wire every chat API already shares.

Bless asks one thing of a model: answer a chat request, whole or as a stream. That is InferenceProvider, and any client conforms in a few lines. Blessed is an InferenceProvider too, so anything that took the model takes the wrapper.

The wire most layers speak

Mistral, OpenAI, vLLM, Ollama, LM Studio and AII's Sewn answer the same chat-completions request. They return the same choices and stream the same server-sent events. Bless's OpenAICompatibleProvider speaks that wire, with presets for the layers it knows by name.

The stream is read byte by byte. Foundation's async lines drop the blank line that ends each event, so the parser takes bytes instead.

Sewn, later

AII's Sewn has no hook between its model and its client yet, so Bless sits in front of it today. The Sewn preset sends the object its chat route requires, and Blessed holds every reply before the host's client sees it. A hook inside Sewn will do better: Sewn writes a conversation into the person's memory before it returns, and the hook must move those writes after the release.

For a whole reply, the hook holds the text before Sewn builds its response. For a stream, it holds every token until the release, then sends the blessed text as one piece.

Any language

A system that is not Swift can still speak Bless. Petitions, verdicts, releases and ledger events are plain JSON, and the bytes a seal signs and a hash covers are written down field by field in the integration guide. Its JavaScript signs a ruling with Web Crypto, and its Python walks a ledger's chain and verifies a seal.

The playground's Witnessed shows the same idea from the other side: a provider that wraps a provider, so the operator can watch the draft being written while Blessed still holds it.
